# review-infrastructure

## 目的

Infrastructure が内側のポート契約を正しく実装し、データ整合性・トランザクション・障害耐性・依存方向を満たしているかレビューする。原則としてコードは変更しない。

## 対象資料

- `CLAUDE.md`、対象 `doc/models/` / API仕様
- Domain / Application / Presentation の実装と関連テスト
- `src/Infrastructure`、`test/Infrastructure`
- マイグレーション、DB設定、テスト設定

## レビュー観点

### ポート契約・マッピング
- Domain / Application のポート契約と実装が一致しているか
- 集約境界を守って読み書きしているか
- DBから復元したモデルが不変条件を満たすか
- SQLとInMemoryの振る舞いに差がないか

### データ整合性
- PK、FK、UNIQUE、CHECK、NOT NULL等の制約が適切か
- 競合更新、楽観ロック／悲観ロック、分離レベルが要件に合うか
- トランザクションの開始・コミット・ロールバックが正しいか
- 部分更新や例外時に不整合が残らないか
- 金額、日時、JSON、NULLの変換に問題がないか

### SQL・運用
- SQLインジェクション対策（パラメーター化）
- インデックスとクエリの妥当性
- 接続プール、タイムアウト、リソース解放
- 秘密情報・個人情報のログ出力がないか
- マイグレーションが安全で再現可能か

### オプションパターン
- EventStore：イベント順序、バージョン競合、追記専用性、再構成
- Outbox：同一トランザクション、配送リース／ロック、再試行、重複配信、滞留監視
- CQRS：Read Model の更新整合性、遅延、再構築
- イベント駆動：冪等性、スキーマ互換性、障害時の再処理

### テスト
- PostgreSQL 17で統合テストされているか
- SQL / InMemory の契約テストがあるか
- 競合・制約違反・ロールバック・障害ケースが検証されているか
- テストが本番DBや共有データを破壊しないか

### アーキテクチャ
- Infrastructure が内側のポートを実装しているか
- Domain / Application にDB固有型が漏れていないか
- Presentation がInfrastructure具象クラスを直接利用していないか

## 指摘形式

ID（INF-001）、重大度（Critical / High / Medium / Low）、対象ファイル・行番号、ポート／仕様根拠、問題・影響、修正方針、必要なテストを含める。

仕様や運用要件が未定義の場合は、欠陥と断定せず「仕様確認事項」とする。

## 禁止事項

- レビュー中に黙ってコード・マイグレーションを変更しない。
- DBに接続してデータ変更・マイグレーション適用をしない。
- 実行していない統合テストを成功と報告しない。

## 報告

Pass / Pass with concerns / Needs changes、指摘一覧、仕様確認事項、実行したテストと未実施テスト、リリース前の確認事項を報告する。
