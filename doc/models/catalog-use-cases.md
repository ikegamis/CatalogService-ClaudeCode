# Catalog ユースケース定義

## UC-CATALOG-001 書籍推薦

### 目的

指定された書籍を理解するための前提書籍を、レビューコメントの内容に基づいて推薦する。

### 入力

- 対象書籍の `BookId`
- レビュー信頼性の閾値（`threshold`）
- 推薦上位件数（必要に見えるが、元資料に具体的な入力仕様はないため未確定）

### 前提条件

- 対象書籍が存在するかどうかの扱いは未確定。
- threshold の設定元・範囲・比較規則は未確定。

### 基本フロー（元PlantUMLに記載された範囲）

1. 対象書籍に関するレビューを取得する。
2. 各レビューについて `Review.isTrustworthy(threshold)` を評価し、信頼できるレビューだけを残す。
3. 信頼できる各レビューについて `Review.extractRecommendedBooks()` を呼び出し、前提書籍タイトルを抽出する。
4. 抽出された前提書籍タイトルの言及頻度を数える。
5. 言及頻度の高い順に並べる。
6. 上位の書籍リストを生成する。

### 出力

- 言及頻度順の推薦書籍リスト。
- 出力項目（BookId、タイトル、言及回数、スコア等）は未確定。

### 業務上の注意

- `Review.isTrustworthy` は単一レビューの信頼性判定である。
- `Review.extractRecommendedBooks` は単一レビューのコメントからタイトル文字列を抽出する。
- 複数レビューの取得・反復・頻度集計・ソートはユースケース全体の処理であり、Review 集約単体の責務ではない。
- 元資料では複数集約からのデータ取得・集計が必要とされている。集約をまたぐ一括更新は定義されていない。

### 未確定事項・確認質問

1. threshold はどこで管理し、どの値域を許容するか。
2. 信頼性スコアは Rating と Comment の品質係数をどのように合成するか。
3. 信頼性スコアが threshold と等しい場合、信頼できると判定するか。
4. 前提書籍タイトルを実在の Book に対応付ける方法は何か。タイトル完全一致か、別名・表記揺れを考慮するか。
5. 同じ書籍が複数表記で抽出された場合、同一書籍として集計する方法は何か。
6. 推薦結果から対象書籍自身を除外するか。
7. 上位何件を返すか。言及頻度が同数の場合の順序はどうするか。
8. 信頼できるレビューが0件、または前提書籍が抽出できない場合の結果はどうするか。
9. Book / Review の取得失敗や、存在しない BookId の場合の業務上の扱いは何か。

## ユースケースとして未定義の操作

元のPlantUMLには、以下の操作の仕様が記載されていないため、ユースケースとして定義しない。

- 書籍登録・更新・削除
- レビュー投稿・更新・削除
- レビュー一覧・詳細の閲覧
- 投稿者の認証・認可
- 推薦結果の保存・履歴参照

これらが必要な場合は、業務フロー・入力・出力・制約を別途定義する。
