# Catalog ドメイン定義

## 1. 対象範囲

本資料は、元のPlantUMLに記載された Book 集約、Review 集約、および書籍推薦機能を定義する。元資料に記載されていない登録・更新・削除などのユースケースは追加しない。

## 2. 集約一覧

| 集約 | 集約ルート | 主な責務 |
|---|---|---|
| 書籍集約 | Book | 書籍ID、タイトル、著者、価格を管理する。 |
| レビュー集約 | Review | 対象書籍、投稿者名、評価、コメントを管理し、レビュー信頼性判定と前提書籍抽出の振る舞いを提供する。 |

## 3. 書籍集約（Book）

### 3.1 属性

- `BookId`：ISBNコードを適用する書籍識別子。
- `Title`：書籍タイトル。
- `Author`：著者。
- `Price`：価格。日本円のみを扱う。

### 3.2 値オブジェクトと制約

#### BookId

- ISBNコードを適用する。
- 元定義では、`978`、グループ（国・地域）番号（日本は `4`）、出版社番号、書名番号からなる12桁に、チェック用の1桁を加える説明がある。
- ISBNコードの正確な桁構成・検証アルゴリズム・出版社番号等の可変長区分は、元定義だけでは実装可能な精度で定まらない。未確定事項を参照する。

#### Title

- 最小長：1
- 最大長：1,000

#### Author

- 最小長：1
- 最大長：100

#### Price

- 通貨：日本円のみ
- 最小値：1
- 最大値：1,000,000
- 小数を許すか、整数円に限定するか、丸め規則は未確定。

### 3.3 振る舞い

元資料で Book の業務メソッドは定義されていない。書籍の基本情報を管理する責務のみが明記されている。

## 4. レビュー集約（Review）

### 4.1 属性

- `ReviewId`：レビュー識別子。
- `BookId`：レビュー対象書籍の識別子。Book 集約への参照はIDで行う。
- `Name`：投稿者名。
- `Rating`：評価。
- `Comment`：コメント。

### 4.2 値オブジェクトと制約

#### ReviewId

- 一意の識別子。
- 生成方式・一意性のスコープは未確定。

#### BookId

- 書籍集約の BookId と同じ書籍識別概念を表す。
- Review は Book 集約全体を内包せず、識別子を保持する。

#### Name

- 最小長：1
- 最大長：50
- 前後空白の扱い、使用可能文字、正規化規則は未確定。

#### Rating

- 1〜5の整数値。
- `getQualityFactor()` は次の式で 0.0〜1.0 に正規化する。

  `qualityFactor = (value - 1) / (5 - 1)`

  | 評価 | 品質係数 |
  |---:|---:|
  | 1 | 0.00 |
  | 2 | 0.25 |
  | 3 | 0.50 |
  | 4 | 0.75 |
  | 5 | 1.00 |

#### Comment

- 最小長：1
- 最大長：1,000
- 誹謗中傷などの不適切なコメントは作成できない。
- 不適切表現の判定基準・判定方法・責務の配置は未確定。
- `getQualityFactor()` はコメント長に基づいて 0.0〜1.0 の範囲で品質を評価する。
  - 10文字未満：0.2
  - 10文字以上100文字未満：0.2から1.0まで線形に増加
  - 100文字以上：1.0
  - 線形区間を上記端点で解釈した場合の式：`0.2 + (length - 10) / 90 * 0.8`
- `extractMatches(pattern: RegExp)` は、指定された正規表現に一致するテキスト部分を抽出する。
- 文字数の数え方（Unicodeコードポイント、UTF-16コード単位、書記素クラスタ等）は未確定。

### 4.3 Review の振る舞い

#### `extractRecommendedBooks(): string[]`

- レビューコメントから前提書籍のタイトルを抽出する。
- 「〜を学んだ後に読むと理解しやすい」というパターンの記述から前提書籍を特定する。
- 前提書籍とは、対象書籍を理解するために必要な基礎知識や前提条件となる書籍を指す。
- 戻り値は書籍タイトル文字列の配列。
- 実際に使用するパターン、タイトル境界の認識、複数候補の扱い、重複排除、誤抽出時の扱いは未確定。

#### `isTrustworthy(threshold: number): boolean`

- 評価品質とコメント品質を組み合わせて信頼性スコアを計算する。
- 信頼性スコアを引数 `threshold` と比較し、レビューが信頼できるかを返す。
- スコアの合成式・各品質係数の重み・閾値の範囲・閾値と同値の場合の判定（`>=` / `>`）は未確定。
- 判定結果はレビューの業務上の信頼性を表し、投稿者本人の認証・本人確認を意味しない。

## 5. 集約間の関連と不変条件

- 1件の Review は1つの BookId を持つ。
- 1件の Book に対して 0件以上の Review が関連する。
- Review は Book 集約を直接保持せず、BookId で参照する。
- 元資料には、Book が存在しない BookId を持つ Review の登録可否や、Book 削除時の Review の扱いは定義されていない。

## 6. Repository / Domain Service の設計上の留意点

元資料は Repository インターフェース名・メソッド・配置層を定義していない。実装時には少なくとも、対象 BookId に紐づくレビュー群を取得する必要があるが、Repository 契約はユースケース設計時に未確定事項を解消してから決める。

書籍推薦は複数 Review の取得・フィルタリング・集計を伴う。`Review.isTrustworthy` と `Review.extractRecommendedBooks` は個々の Review の振る舞いであり、複数レビューを横断する取得・集計のオーケストレーションを Review 集約に持たせない。

集計ロジックを Domain Service と Application Service のどちらに置くかは、推薦ルールのドメイン上の意味とデータ取得の責務を踏まえて設計する。元資料だけでは最終決定しない。

## 7. 未確定事項

1. **信頼性スコア**：Rating と Comment の品質係数をどの式・重みで合成するか。
2. **閾値**：threshold の有効範囲、設定元、比較演算子。
3. **コメント抽出**：前提書籍名を抽出する正規表現・言語表現・誤抽出時の扱い。
4. **書籍名の同定**：抽出タイトルを BookId / Book に対応付ける方法。同名書籍・表記揺れ・版違いの扱い。
5. **推薦結果**：同数順位の並び順、上位件数、推薦対象に自分自身（入力 Book）を含めるか。
6. **投稿者名**：空白・文字種・匿名投稿の扱い。
7. **文字数**：Name、Title、Author、Comment の文字数計測方法。
8. **価格**：整数円限定か、小数を許すか。
9. **ISBN**：ISBN-13 の正確な検証ルール。元定義の桁説明を標準仕様と照合する必要がある。
10. **不適切コメント**：不適切表現の定義と検出・拒否の責務。
11. **識別子**：ReviewId の生成方式と BookId / ReviewId の一意性スコープ。
12. **ライフサイクル**：書籍・レビューの登録、更新、削除、非公開化に関するユースケース。

## 8. 対象外

元資料に定義がないため、以下はこのドメイン定義では追加しない。

- ユーザー認証・認可、投稿者アカウント
- レビューの編集・削除・通報・承認フロー
- 書籍の登録・更新・削除の具体的な操作
- レコメンド結果のキャッシュ・学習・機械学習
- HTTP API、画面、DBスキーマ、外部サービス仕様
