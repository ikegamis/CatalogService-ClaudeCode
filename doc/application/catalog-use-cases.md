# Catalog ユースケース定義

## UC-BOOK-001 書籍登録

### 目的

レビュー対象となる書籍の情報をシステムに登録し、永続化する。

### 入力

- 対象書籍の以下の情報
  - 書籍ID(ISBN)
  - 書籍名
  - 筆者
  - 価格

### 前提条件

- 入力する書籍IDがシステムに登録されていないこと

### 基本フロー
1. 登録するユーザーが入力情報をAPIに渡す
2. 入力情報の書籍IDが登録されていないかチェックする
3. 登録されていなければ入力情報の書籍情報を登録する
   1. 登録されていればエラーを出力する

### 出力
- 登録成功・失敗を示すboolean値
- 成功なら書籍ドメインオブジェクト
- 失敗なら失敗理由のテキスト

## UC-REVIEW-001 レビューの登録

### 目的

特定の書籍に対してレビューを登録する

### 入力

- レビューをつける書籍のID(ISBN)
- レビュー情報
  - 投稿者名
  - レート
  - レビューテキスト

### 前提条件

- レビュー対象の書籍が登録されていること
- レビューテキスト内に前提書籍名が書かれている場合以下の条件を満たすこと
  - 前提書籍名は`『`、`』`で囲まれていること
  - 前提書籍名の後方30文字以内に推薦キーワードが書かれていること。
    - 参照：[推薦キーワード](../domain/models/Review/Review.md#extractrecommendedbooks-string)

### 基本フロー

- 入力条件からレビュードメインオブジェクトを作成する
  - バリデーションチェック
- リポジトリにレビュー情報を永続化する

### 出力

- 成功時：HTTPステータス 2xx
  ```json
  {
    ok: true,
    review: { (レビュードメインオブジェクトのプロパティをJSON形式にしたもの) }
  }
  ```
- 失敗時：HTTPステータス 5xx
  ```json
  {
    ok: false,
    error: (エラー理由の文字列)
  }
  ```

## UC-REVIEW-002 レビューの更新

### 目的

− 間違えて投稿した、レビュー対象の書籍名が間違えていた等の理由でレビューを書き換える

### 入力
- レビュー情報
  - レビューID
  - 書籍ID(ISDN)
  - 投稿者名
  - レート
  - レビューテキスト

### 前提条件

- 更新対象のレビューリポジトリの中に入力のレビューIDが既に登録されていること

### 基本フロー

1. 入力のレビューIDを検索してレビュードメインオブジェクトを再構築する
   1. バリデーションチェック
2. 取得したレビュードメインオブジェクトから更新するレビュードメインオブジェクトを構築する
   1. 両者ともレビューIDは同じ
3. 新しく構築したレビュードメインオブジェクトを永続化する

### 出力

- 成功時：HTTPステータス 2xx
  ```json
  {
    ok: true,
    review: { (レビュードメインオブジェクトのプロパティをJSON形式にしたもの) }
  }
  ```
- 失敗時：HTTPステータス 5xx
  ```json
  {
    ok: false,
    message: (エラー理由の文字列)
  }
  ```

### 業務上の注意

- レビューID以外の入力情報を更新する

## UC-CATALOG-003 レビューの削除

### 目的

- 投稿者が思い直してレビューを削除する

### 入力

- レビューID

### 基本フロー

1. 入力のレビューIDを検索してレビュードメインオブジェクトを再構築する
   1. バリデーションチェック
2. 再構築したレビュードメインオブジェクトのリポジトリから再構築したレビュードメインオブジェクトをさくじょする

### 出力

- 成功時：HTTPステータス2xx
  ```json
  {
    ok: true,
    message: "'{レビューID}' は削除されました"
  }
  ```
- 失敗時：HTTPステータス5xx
  ```json
  {
    ok: false,
    message: (エラー理由の文字列)
  }
  ```

## UC-CATALOG-001 書籍推薦

### 目的

指定された書籍を理解するための前提書籍を、レビューコメントの内容に基づいて推薦する。

### 入力

- 対象書籍の `BookId`
- レビュー信頼性の閾値（`threshold`）。クライアントアプリケーションから渡される
- ~~推薦上位件数（必要に見えるが、元資料に具体的な入力仕様はないため未確定）~~ → 今回は全てのBookを返す

### 前提条件

- ~~対象書籍が存在するかどうかの扱いは未確定~~ → 対象書籍がない場合、成功とし、空の配列を返す
- ~~threshold の設定元・範囲・比較規則は未確定~~ → threshold はクライアントから渡される

### 基本フロー

1. 対象書籍に紐付いている関するレビューの配列を取得する。
2. 各レビューについて `Review.isTrustworthy(threshold)` を評価し、信頼できるレビューだけを残す。
3. 残ったレビューについて `Review.comment.getQualityFactor()` の値をもとにソートする
4. 信頼できる各レビューについて `Review.extractRecommendedBooks()` を呼び出し、前提書籍タイトルを抽出する。
5. 抽出された前提書籍タイトルの言及頻度を数える。
6. 言及頻度の高い順に並べる。
7. 上位の書籍名の配列を生成し、戻り値として返す。

### 出力

- 言及頻度順の推薦書籍名リスト
- ~~出力項目（BookId、タイトル、言及回数、スコア等）は未確定~~
- フォーマット例
  - 成功時：HTTPステータス 2xx
    ```json
    {
      ok: true,
      recommendedBooks: ["書籍タイトル1", "書籍タイトル2", ...]
    }
    ```
  - 失敗時：HTTPステータス 5xx
    ```json
    {
      ok: false
    }
    ```

### 業務上の注意

- `Review.isTrustworthy` は単一レビューの信頼性判定である。
- `Review.extractRecommendedBooks` は単一レビューのコメントから書籍名の文字列の配列を抽出する。
- 複数レビューの取得・反復・頻度集計・ソートはユースケース全体の処理であり、Review 集約単体の責務ではない。
- 元資料では複数集約からのデータ取得・集計が必要とされている。集約をまたぐ一括更新は定義されていない。

## ユースケースとして未定義の操作

以下の操作の仕様が記載されていないため、ユースケースとして定義しない。

- 書籍更新・削除
- レビュー一覧・詳細の閲覧
- 投稿者の認証・認可
- 推薦結果の保存・履歴参照

これらが必要な場合は、業務フロー・入力・出力・制約を別途定義する。
